# Public portfolio starter

Personal portfolio built with Next.js App Router, TypeScript, Tailwind CSS, shadcn/ui, next-intl, and next-themes.

## Getting started

### Requirements

- Node.js 20.9 or newer
- npm

### Local setup

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) to view the app.

Environment variables are validated with Zod in `src/config/env.ts` when imported. Update `.env.local` with project-specific values as needed. `NEXT_PUBLIC_SITE_URL` is the canonical site origin used for metadata, canonical links, the sitemap, and robots.txt; use the local URL during development and the production origin when deploying.

| Variable               | Required for                                                                                         | Example                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------- |
| `NEXT_PUBLIC_SITE_URL` | Canonical URLs, sitemap, robots, and social metadata                                                 | `https://your-domain.com` |
| `CONTACT_EMAIL`        | Recipient of contact form submissions                                                                | `you@example.com`         |
| `CONTACT_FROM_EMAIL`   | Verified sender address for Resend                                                                   | `contact@your-domain.com` |
| `RESEND_API_KEY`       | Sending contact form submissions through Resend                                                      | `re_...`                  |
| `API_BASE_URL`         | Optional external API origin for the HTTP client; leave unset to use this app's `/api/contact` route | `https://api.example.com` |

The contact API returns an unavailable response until `CONTACT_FROM_EMAIL` and `RESEND_API_KEY` are configured. The sender domain must be verified with Resend.

## Languages

The app supports English (`en`), Persian (`fa`), and Portuguese (`pt`) at `/en`, `/fa`, and `/pt`. The root URL redirects to the default English locale. Persian pages use right-to-left layout and Vazirmatn; English and Portuguese use Geist.

Translation messages live in `messages/{en,fa,pt}.json`. The locale routing and request configuration are in `src/i18n/`.

The shared responsive header, mobile navigation, footer, container, and theme controls are in `src/components/`. The color theme follows the system by default and supports light, dark, and system settings.

## Pages

The localized home, about, experience, projects, contact, and project detail pages are implemented in `src/features/`. Project detail paths are generated at build time for each supported locale and project slug. This repository is intentionally safe to fork: the included profile, experience, projects, contact details, and artwork are generic sample content. Replace every sample value before publishing your own portfolio.

## Fork and customize

Use the sample content as a guide, then replace it with your own information:

1. Update your name, bio, location, education, languages, and availability in `messages/en.json`, `messages/fa.json`, and `messages/pt.json`.
2. Replace the single visible sample experience in `src/data/experience.ts` and the sample projects in `src/data/projects.ts` with your own work. Add the project name, description, role, frameworks, libraries, tools, technologies, and methodologies you used.
3. Replace the demo email and LinkedIn URL in `src/features/contact/components/contact-page.tsx`, then set `CONTACT_EMAIL` for contact-form delivery.
4. Add your own project artwork under `public/images/projects/`; do not commit private screenshots, client data, credentials, or personal documents.
5. Set `NEXT_PUBLIC_SITE_URL` and review the generated metadata before deploying.

The visible `you@example.com`, `Your Name`, sample organizations, and placeholder artwork are deliberate hints for developers. They are not real contact details or portfolio claims.

Localized SEO metadata is generated per route, including canonical URLs and `en`, `fa`, and `pt` alternates. The sitemap and robots policy are generated from `src/app/sitemap.ts` and `src/app/robots.ts`. Locale-specific social preview images use translated copy from `messages/` and are generated by `src/app/[locale]/opengraph-image.tsx`; Persian text uses the Vazirmatn font in `public/fonts/`, distributed under the included SIL Open Font License.

## Architecture

```text
Localized App Router pages (thin route components)
  └── Feature components (src/features/<feature>/components)
        └── Feature services (src/services/)
              └── Domain repository interfaces (src/domain/repositories/)
                    └── Repository implementations (src/repositories/)
                          ├── Local typed content (src/data/)
                          └── HTTP client (src/lib/http/httpClient.ts)
                                └── API endpoint constants (src/config/api-endpoints.ts)

Composition root: src/services/index.ts
Contact form → contact service → contact repository → HTTP client → /api/contact
                                                              └── Resend
```

Only `src/lib/http/httpClient.ts` performs application API fetches. API paths are centralized in `src/config/api-endpoints.ts`; domain interfaces keep services independent of repository implementations. `src/services/index.ts` wires the dependencies. Translation messages are in `messages/{en,fa,pt}.json`; locale routing and request configuration are in `src/i18n/`.

## How to add a project or experience

1. Add an item to `src/data/projects.ts` or `src/data/experience.ts`. Follow the existing item type: keep its identifier, images, links, technology stack, and ISO `YYYY-MM-DD` dates in shared fields.
2. Provide `title`, `description`, `imageAlt`, and `role` translations for every supported locale (`en`, `fa`, and `pt`) in the item's `translations` object. Project image alternatives are adapted to each locale automatically.
3. Put project images in `public/images/projects/<project-slug>/` and reference them with public paths such as `/images/projects/<project-slug>/cover.webp`. Keep decorative experience imagery empty or add it under an appropriate `public/images/experiences/` folder.
4. The project and experience repositories adapt source records into locale-specific domain entities. Fetch content through `projectService` or `experienceService` from `src/services/index.ts`, passing the active locale.

Project slugs become statically generated detail-page paths for every locale and are included in the sitemap. `src/data/projects.ts` contains separate sample entries grouped as distinct portfolio projects without invented public URLs. Add verified links and real screenshots when available. The About page contains the categorized skills inventory, and each Experience entry lists the technologies relevant to that role. After adding content, run `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build` to validate it.

To update visible copy or metadata, edit the corresponding message in all three locale files under `messages/`. Keep the JSON keys consistent across locales.

## Deploy to Vercel

1. **Push the project to GitHub.** Create a GitHub repository, commit the project, and push the branch you want to deploy. Do not commit `.env.local` or real API credentials.
2. **Import the repository.** Sign in to [Vercel](https://vercel.com/), choose **Add New → Project**, connect GitHub if prompted, select the repository, and import it. Vercel should detect Next.js and configure the build command as `next build` and the output automatically.
3. **Configure environment variables.** In the project settings, open **Environment Variables** and add:
   - `NEXT_PUBLIC_SITE_URL` — the canonical origin, for example `https://your-project.vercel.app` for the first deployment. Change this to `https://your-domain.com` after assigning the custom domain.
   - `CONTACT_EMAIL` — the inbox that should receive contact submissions.
   - `CONTACT_FROM_EMAIL` — a sender address on a domain verified in Resend.
   - `RESEND_API_KEY` — the secret API key from Resend. Keep it server-side; do not prefix it with `NEXT_PUBLIC_`.
     Apply these variables to the **Production** environment. Add them to **Preview** or **Development** only if those deployments need the contact form and their own correct site URL. Leave `API_BASE_URL` unset unless deliberately sending HTTP client requests to a separate API origin.
4. **Deploy.** Start the deployment from the import screen. For an existing project, trigger a new deployment after adding or changing environment variables; environment changes do not update deployments that have already been built.
5. **Add a custom domain.** In the Vercel project, open **Settings → Domains**, enter your domain, and follow Vercel's instructions to add the displayed DNS records at your domain registrar. Wait until Vercel verifies the domain and provisions HTTPS.
6. **Set the canonical production origin.** Set `NEXT_PUBLIC_SITE_URL` to the final HTTPS origin (for example `https://your-domain.com`, using the preferred `www` or apex host). Apply it to Production and redeploy. Confirm the canonical links, sitemap at `/sitemap.xml`, robots file at `/robots.txt`, localized routes, social preview image, and contact form on the deployed site.

The values in `.env.example` are placeholders; replace them with your real email configuration before publishing.
